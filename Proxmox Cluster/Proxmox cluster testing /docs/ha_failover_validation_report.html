4. Datacenter High Availability Policy Configuration

Critical Finding: By default, Proxmox VE datacenter policy uses shutdown_policy=conditional. In this default configuration, if an operator issues a reboot command, Proxmox freezes running HA virtual machines on the local server and does not migrate them, causing workload downtime during the reboot.

To fulfill the production mandate of automatic evacuation on reboot or shutdown, the cluster datacenter configuration was updated in /etc/pve/datacenter.cfg (synchronized across all nodes via pmxcfs):

# Updated /etc/pve/datacenter.cfg keyboard: en-us ha: shutdown_policy=migrate

Mechanism: With shutdown_policy=migrate, systemd shutdown hooks notify pve-ha-crm. The HA manager intercepts the power-off sequence, issues live migration commands to evacuate all running guests to healthy quorum members, and releases the host for reboot only after all guests are safely operational elsewhere.

8. Unplanned Failure (Hard Crash / Power Loss) Dynamics Analysis

In contrast to a planned host reboot (which performs graceful live evacuation), an abrupt physical hardware crash, power outage, or sudden network isolation triggers Watchdog Fencing & HA Cold Recovery:

Ceph Workload (VM 9001) Failure Recovery

RTO (Recovery Time): ~60–90 seconds.
RPO (Data Loss Point): 0 seconds (RPO = 0).
Mechanism: When a host suddenly dies, surviving nodes maintain Corosync quorum (2/3 votes). After the 60-second fencing confirmation window to prevent split-brain, CRM restarts VM 9001 on prox22 or prox23. Because Ceph synchronously writes to 3 replicas, zero disk data is lost.

ZFS Replicated Workload (VM 9002) Failure Recovery

RTO (Recovery Time): ~60–120 seconds.
RPO (Data Loss Point): Dependent on replication interval (≤ 30 min).
Mechanism: Upon primary host crash, CRM boots VM 9002 on a surviving replica host from the most recent completed ZFS snapshot. Uncommitted writes occurring after the last scheduled replication window are unrecoverable from the crashed local disk.

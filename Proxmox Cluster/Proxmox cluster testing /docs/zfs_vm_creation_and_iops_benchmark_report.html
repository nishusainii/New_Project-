This engineering report presents empirical benchmarks and deep production testing conducted on the 3-node Proxmox VE cluster cisai-pve. 3. Benchmarking Methodology: Direct I/O (Unbuffered dd)

Why Direct I/O (oflag=direct / iflag=direct)? Standard filesystem writes pass through Linux page cache buffers in RAM, inflating apparent speeds. To evaluate true enterprise hardware performance, all tests bypass host OS page caching completely by sending synchronous direct block I/O requests directly to the zvol block controller:
• IOPS Calculation: IOPS = Total Transferred Blocks / Execution Duration (seconds)
• Latency Calculation: Average Latency (ms) = (Execution Duration (seconds) × 1000) / Total Blocks
4KB Block Profile

Simulates relational database transactions (PostgreSQL / MySQL / Oracle), OLTP queries, and small random filesystem I/O operations.

64KB Block Profile

Simulates enterprise web application servers, message broker queues (Kafka / RabbitMQ), and standard multi-threaded web application I/O.

1MB Block Profile

Simulates large sequential streaming, bulk data ingestion, video/media processing, and backup storage operations.

When to Choose ZFS RAIDZ2 Storage

Workloads: High-transaction databases (PostgreSQL, MySQL, Redis), local analytics, high-speed compilations, or high-throughput file ingestion.
Advantage: Exceptional raw I/O throughput (up to 4.0 GB/s) and near-zero write latency (0.021 ms).
Failover Mechanism: Periodic pvesr replication (asynchronous RPO ≤ schedule).

When to Choose Ceph Shared Storage

Workloads: Mission-critical production applications, multi-tenant VMs, and web clusters requiring zero downtime.
Advantage: Uniform shared storage accessible on all nodes simultaneously. Enables true zero-downtime live migration and instant cold failover with RPO = 0.
Tradeoff: Lower single-stream throughput due to 3-way network replication.

10. Suggested Additional Deep Production Test Scenarios

For continuing resilience validation, the following test scenarios are recommended for scheduled staging windows:

1. Single Disk Degradation & Hot-Replace Test

Test: Offline a single drive in the 7-disk RAIDZ2 pool (zpool offline zfs-ha <disk>).
Measure: Verify pool remains ONLINE (DEGRADED) with zero VM I/O interruption, then trigger zpool online and measure scrub rebuild speed.

2. High-Stress Live Migration Under Heavy I/O

Test: Execute continuous dd write load inside VM 9001 while initiating cross-node live migration to prox22.
Measure: Validate QEMU pre-copy dirty-memory convergence and verify zero transaction drops.

3. Ceph OSD Simulated Failure & PG Peering

Test: Stop one Ceph OSD service (systemctl stop ceph-osd@0).
Measure: Verify placement groups transition to active+undersized and measure automated data re-replication to surviving OSDs.

4. Dedicated 10G Migration Network Isolation

Test: Configure migration: network=192.168.10.0/24 in datacenter.cfg.
Measure: Isolate bulk memory copy traffic from management vmbr0 to achieve sub-15s live migrations on 4GB guests.

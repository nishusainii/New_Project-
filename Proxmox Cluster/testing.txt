Recommended command for your current cluster

Your cluster is already HEALTH_WARN because prox23, its monitor, and OSDs are unavailable. First run only the safe health collection:

sudo /usr/local/sbin/ceph-validation-suite --mode health


This does not run storage performance tests or stop anything.

For performance testing with the existing vm-rbd pool:

sudo /usr/local/sbin/ceph-validation-suite \
  --mode validate \
  --pool vm-rbd \
  --continue-degraded \
  --bench-seconds 30 \
  --timeout 300


The --continue-degraded parameter is deliberately required while the cluster baseline is not HEALTH_OK. Without it, performance tests are skipped rather than accidentally benchmarking an unhealthy cluster.

Disruptive test protection

The disruptive modes require both:

The --allow-destructive parameter.
An exact interactive confirmation phrase.

For example, the OSD test asks you to type:

RUN-osd-failure


If the phrase is incorrect, the test is cancelled.

Do not run an OSD or MON failure test while prox23 remains offline. Your cluster is already degraded and has reduced redundancy.

OSD failure test

Run this only after the cluster is stable and choose an OSD hosted on the local machine running the script, because systemctl controls only local services:

sudo /usr/local/sbin/ceph-validation-suite \
  --mode osd-failure \
  --osd 5 \
  --timeout 600 \
  --allow-destructive


The script:

Verifies that the OSD exists.
Saves cluster evidence.
Records whether noout was already enabled.
Sets noout if needed.
Marks the OSD out.
Stops and starts its systemd service.
Marks it back in.
Restores the original noout condition.
Waits for the original baseline state or HEALTH_OK.
Stops waiting after the configured timeout.
Monitor failure test

Only target a monitor running on the local host:

sudo /usr/local/sbin/ceph-validation-suite \
  --mode mon-failure \
  --mon prox24 \
  --timeout 300 \
  --allow-destructive


Do not run that command now while prox23 is unavailable. Stopping another monitor could remove quorum.

Temporary network partition
sudo /usr/local/sbin/ceph-validation-suite \
  --mode network-partition \
  --subnet 10.31.122.23/32 \
  --partition-seconds 30 \
  --timeout 300 \
  --allow-destructive


Safety controls:

Maximum partition duration is 300 seconds.
The rule uses the comment ceph-validation.
The script removes only the rule it added.
EXIT, INT, and TERM traps attempt rule cleanup if the run is interrupted.
Current iptables configuration is saved before the change.

Avoid running this through the same network path that provides your SSH management connection. Prefer console access.

Bounded disk-space test

This version does not intentionally fill an entire OSD. It creates a size-limited temporary test file:

sudo /usr/local/sbin/ceph-validation-suite \
  --mode disk-space \
  --path /var/lib/ceph/osd/ceph-32 \
  --test-mib 1024 \
  --timeout 300 \
  --allow-destructive


Safety controls:

Maximum temporary file size is 10,240 MiB.
Requires an additional 1,024 MiB of free-space headroom.
Deletes the test file after the check.
Cleanup trap attempts deletion if interrupted.

This is a bounded disk-space pressure test, not a true Ceph FULL threshold test. That limitation is intentional because filling a live OSD can disrupt writes and create serious recovery risk.

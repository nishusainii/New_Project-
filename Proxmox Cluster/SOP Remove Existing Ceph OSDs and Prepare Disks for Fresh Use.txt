

Below is the complete CLI-only process you followed on **prox24** and **prox23**. It includes identification, safety checks, OSD shutdown, disk cleanup, and final validation.

> **Warning:** This procedure permanently deletes all Ceph data from `/dev/sda` through `/dev/sdl`. In your environment, `/dev/sdm` is the Proxmox OS disk and must never be included.

## 6. Automatically extract the local OSD IDs

This method avoids using OSD IDs from another Proxmox node.

done  

`

Validate every service:

for id in "${OSD_IDS[@]}"; do  

printf "osd.%-3s : " "$id"  

systemctl is-active "ceph-osd@${id}.service" 2>/dev/null || true  

done  

Expected state:

inactive

Check that no OSD process remains:

pgrep -a ceph-osd ||  

echo "No ceph-osd processes are running"

Ceph refuses to zap a device if its associated OSD service is still running. [[docs.ceph.com]](https://docs.ceph.com/en/latest/ceph-volume/lvm/zap/)

## 10. Permanently remove the old Ceph structures

for disk in "${TARGET_DISKS[@]}"; do  

echo  

echo "===== Zapping $disk ====="  

ceph-volume lvm zap "$disk" --destroy  

done

The successful result for each disk was:

Zapping successful for: <Raw Device: /dev/sdX>

This operation:

1. Unmounted the Ceph OSD directory.
2. Removed BlueStore metadata.
3. Removed the `osd-block-*` logical volume.
4. Removed the associated `ceph-*` volume group.
5. Removed the LVM PV label.
6. Cleared the beginning of the disk.

The `--destroy` option is designed to remove Ceph-created LVs and VGs from a raw device so that it can be reused. [[docs.ceph.com]](https://docs.ceph.com/en/latest/ceph-volume/lvm/zap/)

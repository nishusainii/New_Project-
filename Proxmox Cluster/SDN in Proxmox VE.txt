### What is SDN in Proxmox VE?

**Software-Defined Networking (SDN)** in Proxmox VE is a centralized network virtualization layer. Instead of manually logging into each Proxmox node to configure `/etc/network/interfaces`, Linux bridges, and VLANs, Proxmox SDN allows you to configure virtual networks at the **Datacenter level**.

The cluster then automatically distributes and synchronizes the network configuration across all cluster nodes.

---

### Is SDN Useful in a Proxmox VE Cluster? (Use Cases & Benefits)

**Yes, SDN is exceptionally useful in a multi-node cluster.** In fact, SDN provides the most value when you have two or more nodes:

| Feature / Benefit | Traditional Linux Bridges (`vmbrX`) | Proxmox SDN |
| :--- | :--- | :--- |
| **Cluster-Wide Sync** | Manual setup on every node in `/etc/network/interfaces`. | Configure once at **Datacenter**; synced cluster-wide. |
| **Overlay Networks (VXLAN / EVPN)** | Requires manual setup of tunnels or complex routing. | Native VXLAN/EVPN support; creates private L2 networks over standard L3 physical networks. |
| **No Physical Switch Changes** | Creating a new VLAN requires configuring 802.1Q tags on physical switches. | Overlay zones (like VXLAN) work over existing IP connectivity without touching physical switches. |
| **Live Migration Consistency** | Bridges must match exact names across all nodes. | VNets exist identically on all nodes, ensuring uninterrupted live migration. |

### Core Concepts of Proxmox SDN

1. **Zone**: Defines the network type and topology:
   - **Simple**: Isolated local bridge on each node (good for single-node or NAT setups).
   - **VLAN**: Standard 802.1Q VLANs using an existing physical bridge.
   - **QinQ**: Double-tagged VLANs for nested carrier-grade isolation.
   - **VXLAN**: Layer 2 overlay tunneled over Layer 3 UDP (port 4789). **Best for multi-node clusters** because VMs can talk on the same subnet across different hosts without modifying physical switch VLAN configs.
   - **EVPN (BGP)**: Enterprise-scale VXLAN using FRRouting / BGP control plane (ideal for multi-rack or datacenter deployments).
2. **VNet (Virtual Network)**: A virtual switch/bridge (e.g., `vnet10`) created within a Zone. VMs and containers attach their NICs to this VNet.
3. **Subnet**: An IP network (CIDR) associated with a VNet, defining gateway, SNAT/NAT, and DHCP ranges.
4. **IPAM (IP Address Management)**: Automatically tracks and assigns IP addresses to VMs/containers (built-in PVE IPAM, Netbox, or phpIPAM).
5. **Controllers**: Used for advanced setups (EVPN / BGP) to exchange routing information automatically.

### Step-by-Step: How to Implement SDN in Proxmox VE

#### Step 1: Verify Prerequisites
Proxmox VE 8.1+ comes with SDN core packages pre-installed. Ensure `ifupdown2` is used for reload capabilities without rebooting:

```bash
apt update
apt install ifupdown2 libpve-network-perl
```

Ensure your `/etc/network/interfaces` on all nodes includes the SDN directory:
```text
source /etc/network/interfaces.d/*
```

*(Optional: If you want automatic DHCP for SDN subnets, install dnsmasq on your nodes: `apt install dnsmasq -y && systemctl disable --now dnsmasq`)*

---

#### Step 2: Choose and Create a Zone
1. Open the Proxmox Web GUI.
2. Go to **Datacenter** $\rightarrow$ **SDN** $\rightarrow$ **Zones**.
3. Click **Add** and choose your zone type:
   - **For cluster communication without changing physical switches:** Choose **VXLAN**.
     - **ID**: `vxlan-zone`
     - **Peers**: Add the IP addresses of all your Proxmox cluster nodes (or use multicast).
     - **MTU**: `1450` *(VXLAN adds 50 bytes of overhead to the standard 1500 MTU)*.
   - **For traditional VLAN tagging:** Choose **VLAN**.
     - **ID**: `vlan-zone`
     - **Bridge**: `vmbr0`

---

#### Step 3: Create a VNet (Virtual Network)
1. Go to **Datacenter** $\rightarrow$ **SDN** $\rightarrow$ **VNets**.
2. Click **Create**:
   - **Name**: e.g., `vnet10`
   - **Zone**: Select the zone created in Step 2 (`vxlan-zone`).
   - **Tag**: e.g., `10010` (VNet tag / VXLAN Network Identifier - VNI).

---

#### Step 4: Add Subnet & Gateway (Optional IPAM / DHCP)
1. Select the newly created VNet (`vnet10`) in the VNets list.
2. Under the lower pane, click **Subnets** $\rightarrow$ **Create**:
   - **Subnet**: `10.10.10.0/24`
   - **Gateway**: `10.10.10.1`
   - **SNAT**: Check this box if you want VMs on this private VNet to have outbound internet access through the Proxmox host.
   - **DHCP**: Enable if `dnsmasq` is configured.

---

#### Step 5: Apply the Configuration
SDN changes are staged first and do not go live until applied:
1. Go to **Datacenter** $\rightarrow$ **SDN**.
2. Click the blue **Apply** button at the top.
3. Proxmox will reload networking across the entire cluster.

---

#### Step 6: Connect VMs or Containers to the VNet
1. Go to any VM or Container $\rightarrow$ **Hardware** $\rightarrow$ **Network Device**.
2. In the **Bridge** dropdown, choose your new VNet (`vnet10`).
3. Click **OK**.

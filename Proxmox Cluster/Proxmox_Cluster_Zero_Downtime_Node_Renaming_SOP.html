Execution Summary: Officially, Proxmox VE does not support in-place node renaming for clustered nodes due to hardcoded dependencies across Corosync, Ceph CRUSH hierarchies, pmxcfs cluster directories, and SSL certificates. This document outlines the rolling orchestration methodology used to safely rename all three physical hypervisors from prox22, prox23, prox24 to prox022, prox023, prox024 while maintaining 100% guest uptime for live production VMs.

2. Technical Strategy: Why Rolling Execution Works Zero Downtime Principles
  • Dual-DNS Alias Resolution: Updating /etc/hosts with both old and new names across all nodes ensures that Corosync and SSH can resolve all peers continuously during the transition window.
  • Ceph CRUSH Bucket Renaming: Running ceph osd crush rename-bucket <old> <new> updates the topology map instantly without triggering any data rebalancing or I/O degradation.
  • Ceph Monitor/Manager Re-creation: Because Ceph requires 2 of 3 monitors for quorum, destroying 1 monitor at a time on the maintenance node allows the cluster to maintain quorum on the surviving 2 nodes.
  • Corosync Version Incrementing: Incrementing config_version in /etc/pve/corosync.conf propagates the new nodelist across pmxcfs automatically.
  • Preservation of Local LVM Volumes: Virtual machines with disks on local-lvm (e.g. VM 106 with 250GB) never leave their physical host. Only the VM configuration pointer in /etc/pve/nodes/ moves to the new folder.

4. Phase 1: Rolling Rename of Node 1 (prox23 ➔ prox023) Node 1 Procedure
Step 1.1: Live-Migrate VM 9003 to prox24
Empties all workloads from prox23 before initiating maintenance.
ha-manager migrate vm:9003 prox24
Step 1.2: Destroy Ceph MON & MGR on prox23
Run directly on 10.31.6.173. Quorum remains healthy (2/3 monitors online).
pveceph mon destroy prox23
pveceph mgr destroy prox23
Step 1.3: Rename Ceph CRUSH Host Bucket
Prevents placement group (PG) reshuffling and maintains OSD health.
ceph osd crush rename-bucket prox23 prox023
Step 1.4: Place Node in HA Maintenance & Update Configs
Disables watchdog fencing and updates Corosync, Storage, and Replication.
ha-manager crm-command node-maintenance enable prox23
sed -i "s/prox23/prox023/g" /etc/pve/storage.cfg
sed -i "s/prox23/prox023/g" /etc/pve/replication.cfg
sed -i "s/name: prox23/name: prox023/g" /etc/pve/corosync.conf
sed -i "s/config_version: 4/config_version: 5/g" /etc/pve/corosync.conf
Step 1.5: Set Hostname, Restart Services & Regenerate SSL (on 10.31.6.173)
Applies new hostname and rebuilds node certificates.
hostnamectl set-hostname prox023
echo prox023 > /etc/hostname
systemctl restart pve-cluster corosync
pvecm updatecerts -f
systemctl restart pvedaemon pveproxy pvestatd pve-ha-lrm pve-ha-crm
Step 1.6: Re-establish Ceph Daemons & Disable Maintenance
Rebuilds mon and mgr daemons under the new identity and restores HA.
pveceph mon create
pveceph mgr create
ha-manager crm-command node-maintenance disable prox023
rm -rf /etc/pve/nodes/prox23

1. Executive Summary & Migration Motivation Operational Background

This document details the engineering runbook, execution procedure, and post-migration validation for transitioning the primary management and VM bridge interface (vmbr0) physical uplink from nic1 to nic0 across the 3-node production Proxmox VE cluster (prox022, prox023, prox024).

Original Architecture & Role of nic1: Previously, vmbr0 was slaved exclusively to physical port nic1 (Broadcom BCM5720 Gigabit PCIe LOM Port 2). This single physical interface carried all cluster control-plane traffic (management IP 10.31.6.x/22, default gateway 10.31.4.1, Corosync cluster heartbeat, Proxmox Web GUI port 8006, SSH port 22), as well as bridge virtual networking for all running VMs.
Identified Hardware Bottleneck (prox024): During proactive hardware audits, physical interface nic1 on prox024 was observed to have degraded from Gigabit speed down to 100 Mb/s Half/Full duplex due to cable/negotiation wear. In contrast, nic0 (LOM Port 1) was physically cabled, link-detected, and operating at full 1000 Mb/s Full Duplex across all nodes.
Migration Outcome: All three nodes were safely migrated to nic0 in a zero-downtime rolling sequence protected by automated watchdog timers. The 100 Mb/s throttle on prox024 was completely resolved. All 5 production VMs remained online without a single packet dropped.

4. Rolling Migration Procedure & Watchdog Failsafe Execution Methodology

The migration was executed sequentially: prox023 (canary) → prox024 → prox022 (CRM Master). An automated watchdog script was launched in the background on each node prior to applying changes. If gateway connectivity failed, the watchdog automatically restored the backup and reloaded networking:

Automated Watchdog Safety Pattern: 
# 1. Backup existing configuration
cp /etc/network/interfaces /etc/network/interfaces.bak.switch_nic0

# 2. Arm failsafe watchdog timer in background
nohup bash -c '
    sleep 25
    if ! ping -c 2 -W 2 10.31.4.1 >/dev/null 2>&1; then
        logger "Watchdog triggered: reverting to interfaces.bak.switch_nic0"
        cp /etc/network/interfaces.bak.switch_nic0 /etc/network/interfaces
        mv /run/network/ifstatenew.bak /run/network/ifstatenew 2>/dev/null || true
        ifreload -a
    fi
' >/dev/null 2>&1 &
WATCHDOG_PID=$!

# 3. Clean stale SDN state, swap bridge port, and reload
mv /run/network/ifstatenew /run/network/ifstatenew.bak 2>/dev/null || true
sed -i 's/bridge-ports nic1/bridge-ports nic0/' /etc/network/interfaces
ifreload -a

# 4. Disarm watchdog upon successful ping validation
ping -c 3 10.31.4.1 && ping -c 2 10.31.6.172 && kill $WATCHDOG_PID

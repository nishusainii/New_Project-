  ## 1. Intended Architecture

  ### Architectural Principle

  Deploying consumer desktop distributions (such as Ubuntu Desktop) introduces substantial bloat: background daemons, Snap store overhead, media players, games, and
  GNOME Shell memory footprints exceeding 1.8 GB RAM per idle session.

  In this architecture, Ubuntu Server 24.04 LTS serves as the minimal operating-system base. On top of this clean baseline:

  1. XFCE Desktop Environment is installed: Provides an enterprise, lightweight X11 desktop environment consuming only ~350 MB to 500 MB RAM per session with minimal
  CPU load and low latency over virtual display protocols.
  2. xrdp with xorgxrdp is deployed: Enables standards-compliant RDP (Remote Desktop Protocol) client connectivity across Windows, macOS, Linux (Remmina), and thin-
  client terminals.
  3. Alternative Access Transports: SPICE (via Proxmox native console or remote-viewer), NoMachine, or VDI connection brokers (e.g., OpenUDS, Apache Guacamole,
  ThinLinc, Leostream) can be layered on top without re-architecting the base image.

  ### VM Specifications Summary

  • Firmware & Chipset: OVMF UEFI + q35 PCIe architecture + 4MB EFI Disk
  • Storage: VirtIO SCSI Single (virtio-scsi-single) with dedicated IOThread, discard=on (TRIM), and SSD emulation (ssd=1)
  • Networking: VirtIO paravirtualized NIC with optional VLAN tagging
  • Agent: QEMU Guest Agent (qemu-guest-agent) enabled
  • Provisioning: cloud-init via attached virtual drive

  ## 2. State Assumptions and Limitations

  ### Assumptions

  1. Proxmox VE is installed, reachable via network, and managed by an authorized administrator.
  2. A storage pool supporting VM disk images (images) exists (e.g., local-lvm, local-zfs, ceph, or NFS-Storage).
  3. An active network bridge (e.g., vmbr0) exists on the host with connectivity to a provisioning DHCP service or routed subnet.
  4. Target VM IDs and Template IDs are reserved and confirmed unused prior to execution.

  ### Proxmox VM Template vs. Complete VDI Platform

  A Proxmox VM Template is an immutable master virtual machine image and hardware definition.

  • What Proxmox Provides: Rapid linked/full cloning, live snapshotting, VM scheduling, disk resizing, and cluster migration.
  • What Proxmox Does NOT Provide: User entitlement brokering, dynamic non-persistent pool recycling upon logout, user-session load balancing, or HTML5 clientless
  browser gateways.
  • Centralized Brokering Options: If automated pooling and entitlement management are needed, combine Proxmox with:
      • OpenUDS: Multi-platform open-source VDI connection broker with native Proxmox VE API provider.
      • Apache Guacamole: Clientless HTML5 browser gateway for RDP/SSH/VNC.
      • Leostream: Enterprise broker providing dynamic desktop pool assignment and Active Directory integration.


  ### Persistent vs. Non-Persistent VDI Models

  • Persistent VDI (Full Clone): Independent disk copy (--full 1). The VM retains all installed user packages, local configurations, and files across reboots. Backed
  up individually via Proxmox Backup Server or vzdump.
  • Non-Persistent VDI (Linked Clone): Differencing disk pointing to the base template disk (--full 0). Provisioned in seconds. Highly storage efficient. All guest
  state is ephemeral and discarded upon VM destroy/reset. Requires user profiles to be redirected to network storage (NFS/SMB/SSSD).

  ## 5. Image Creation Approaches

  ### Method A: Official Cloud Image (Preferred)

  • Mechanism: Download noble-server-cloudimg-amd64.img directly from Ubuntu's cloud image repository, verify cryptographic SHA256 checksum, import into Proxmox via
  qm importdisk, and attach a cloud-init drive.
  • Advantages: 100% deterministic, zero human error during OS installation, fast (provisions in < 2 minutes), clean minimal OS baseline without desktop installer
  baggage.
  • Limitations: Requires outgoing HTTPS connectivity from the Proxmox host (or manual copy of the cloud image).

  ### Method B: ISO Installation

  • Mechanism: Mount Ubuntu Server 24.04 ISO, manually or via autoinstall navigate partition wizards, and manually configure packages.
  • Advantages: Compatible with completely disconnected air-gapped environments.
  • Limitations: Slower, inconsistent partition layout, requires manual cleanup of installer cache and log residue.

  ## 6. Create the Proxmox Build VM

  ### 6.1 Proxmox Web GUI Instructions

  1. Log in to Proxmox Web UI (https://<pve-node>:8006).
  2. Click Create VM:
      • General: Node: <node>, VM ID: 9000, Name: ubuntu-2404-vdi-gold-build. Check Advanced.
      • OS: Select Do not use any media. Guest OS Type: Linux, Version: 6.x - 2.6 Kernel.
      • System: Machine: q35, BIOS: OVMF (UEFI), Check Add EFI Disk (Storage: local-lvm, Pre-Enrolled Keys checked). SCSI Controller: VirtIO SCSI Single. Check QEMU
      Agent.
      • Disks: Delete the default SCSI/IDE disk created by the wizard.
      • CPU: Sockets: 1, Cores: 4, Type: host (provides AVX2/AES hardware acceleration for smooth video rendering).
      • Memory: 4096 MB. Disable memory ballooning (balloon: 0) to prevent latency spikes during user graphical workloads.
      • Network: Bridge: vmbr0, Model: VirtIO (paravirtualized).
  3. Under Hardware:
      • Click Add -> CloudInit Drive (Bus: IDE 2, Storage: local-lvm).
      • Click Add -> Serial Port (Port 0).
      • Edit Display: Set to Serial terminal 0 (or SPICE (qxl) if SPICE testing is desired).
  4. Under Cloud-Init:
      • Set User: vdiadmin, inject your public SSH key, DNS: 10.31.0.1, IP: DHCP.

  ### 6.2 Equivalent qm CLI Commands (Scriptable & Idempotent)

    # [CHANGE] 1. Verify VM ID is Unused
    if qm status "${VM_ID}" &>/dev/null; then
        echo "[-] ERROR: VM ID ${VM_ID} is already in use!" >&2
        exit 1
    fi
    
    # [CHANGE] 2. Download and Verify Cloud Image Checksum
    mkdir -p "${IMAGE_DIR}"
    cd "${IMAGE_DIR}"
    
    if [[ ! -f "${UBUNTU_IMAGE}" ]]; then
        echo "[*] Downloading Ubuntu 24.04 Cloud Image..."
        wget -q --show-progress "https://cloud-images.ubuntu.com/noble/current/${UBUNTU_IMAGE}"
        wget -q "https://cloud-images.ubuntu.com/noble/current/SHA256SUMS"
    fi
    
    echo "[*] Verifying SHA256 checksum..."
    EXPECTED_HASH=$(grep "${UBUNTU_IMAGE}" SHA256SUMS | awk '{print $1}')
    ACTUAL_HASH=$(sha256sum "${UBUNTU_IMAGE}" | awk '{print $1}')
    
    if [[ "${EXPECTED_HASH}" != "${ACTUAL_HASH}" ]]; then
        echo "[-] FATAL: Checksum verification failed!" >&2
        exit 1
    fi
    echo "[+] Checksum Verified: ${ACTUAL_HASH}"
    
    # [CHANGE] 3. Create Base VM with q35, OVMF, VirtIO-SCSI-Single, and QEMU Guest Agent
    qm create "${VM_ID}" \
        --name "${VM_NAME}" \
        --machine q35 \
        --bios ovmf \
        --cpu host \
        --cores "${CORES}" \
        --sockets 1 \
        --memory "${MEMORY}" \
        --balloon 0 \
        --scsihw virtio-scsi-single \
        --net0 "virtio,bridge=${BRIDGE}${VLAN_ID:+,tag=${VLAN_ID}}" \
        --agent enabled=1,fstrim_cloned_disks=1 \
        --vga serial0 \
        --serial0 socket \
        --ostype l26
    
    # [CHANGE] 4. Allocate 4MB OVMF EFI Disk with Pre-Enrolled Keys
    qm set "${VM_ID}" --efidisk0 "${STORAGE}:0,pre-enrolled-keys=1,efitype=4m"
    
    # [CHANGE] 5. Import Cloud Disk Image into Target Storage Pool
    qm importdisk "${VM_ID}" "${IMAGE_PATH}" "${STORAGE}"
    
    # Retrieve imported volume name
    IMPORTED_VOL=$(qm config "${VM_ID}" | grep -o "unused[0-9]" | head -n1)
    
    # [CHANGE] 6. Attach as Primary Boot Disk with Discard (TRIM) and SSD Emulation
    qm set "${VM_ID}" --scsi0 "${STORAGE}:${IMPORTED_VOL},discard=on,ssd=1,iothread=1"
    
    # [CHANGE] 7. Resize Disk to Target Capacity
    qm disk resize "${VM_ID}" scsi0 "${DISK_SIZE}"
    
    # [CHANGE] 8. Attach Cloud-Init Drive
    qm set "${VM_ID}" --ide2 "${STORAGE}:cloudinit"
    
    # [CHANGE] 9. Configure Boot Order & Cloud-Init Parameters
    qm set "${VM_ID}" --boot order=scsi0
    qm set "${VM_ID}" --ciuser "${CI_USER}"
    qm set "${VM_ID}" --sshkeys "${SSH_PUBLIC_KEY_FILE}"
    qm set "${VM_ID}" --ipconfig0 "${IP_CONFIG}"
    qm set "${VM_ID}" --nameserver "${DNS_SERVER}"
    qm set "${VM_ID}" --searchdomain "${DNS_DOMAIN}"
    
    # [VALIDATION] Verify Complete VM Configuration
    qm config "${VM_ID}"

  ## 7. Base Ubuntu Configuration

  Power on the VM from the Proxmox host and connect via SSH:

    # [CHANGE] Start the VM
    qm start "${VM_ID}"
    
    # Wait for IP address via QEMU Guest Agent
    BUILD_IP=""
    while [[ -z "${BUILD_IP}" ]]; do
        echo "[*] Waiting for QEMU Guest Agent to report IP address..."
        sleep 3
        BUILD_IP=$(qm guest cmd "${VM_ID}" network-get-interfaces 2>/dev/null | jq -r '.[].["ip-addresses"][]? | select(.["ip-address-type"]=="ipv4" and .["ip-
  address"]!="127.0.0.1") | .["ip-address"]' | head -n1 || true)
    done
    echo "[+] Build VM active at: ${BUILD_IP}"
    
    # Connect to Guest Shell
    ssh -i "${SSH_PUBLIC_KEY_FILE}" "${CI_USER}@${BUILD_IP}"

  ## 9. Remote Desktop Configuration (xrdp)

  ### 9.1 Service Setup & Fixes for Common Issues

    # [CHANGE] 1. Install xrdp and the high-performance xorgxrdp backend
    sudo apt-get install -y --no-install-recommends xrdp xorgxrdp
    
    # [CHANGE] 2. Grant xrdp user access to SSL certificates
    sudo adduser xrdp ssl-cert
    
    # [CHANGE] 3. Configure Default System-Wide X Session
    sudo update-alternatives --set x-session-manager /usr/bin/xfce4-session
    
    # Create system-wide fallback template in /etc/skel
    sudo tee /etc/skel/.xsession <<'EOF'
    #!/bin/sh
    export GNOME_SHELL_SESSION_MODE=xfce
    export XDG_CURRENT_DESKTOP=XFCE
    export XDG_SESSION_DESKTOP=xfce
    exec /usr/bin/xfce4-session
    EOF
    sudo chmod +x /etc/skel/.xsession
    
    # [CHANGE] 4. Configure /etc/xrdp/startwm.sh to Prevent Black Screen on Login
    sudo tee /etc/xrdp/startwm.sh <<'EOF'
    #!/bin/sh
    if [ -r /etc/default/locale ]; then
        . /etc/default/locale
        export LANG LANGUAGE
    fi
    
    # Reset bus environment variables to avoid session bus locking
    unset DBUS_SESSION_BUS_ADDRESS
    unset XDG_RUNTIME_DIR
    
    export XDG_CURRENT_DESKTOP=XFCE
    export XDG_SESSION_DESKTOP=xfce
    exec /usr/bin/xfce4-session
    EOF
    sudo chmod +x /etc/xrdp/startwm.sh
    
    # [CHANGE] 5. Configure Session Parameters in /etc/xrdp/sesman.ini
    sudo sed -i 's/^KillDisconnected=.*/KillDisconnected=false/' /etc/xrdp/sesman.ini
    sudo sed -i 's/^DisconnectedTimeLimit=.*/DisconnectedTimeLimit=0/' /etc/xrdp/sesman.ini
    sudo sed -i 's/^IdleTimeLimit=.*/IdleTimeLimit=0/' /etc/xrdp/sesman.ini
    sudo sed -i 's/^MaxSessions=.*/MaxSessions=50/' /etc/xrdp/sesman.ini
    
    # [CHANGE] 6. Resolve PolicyKit Popups for Color Manager and NetworkManager
    sudo mkdir -p /etc/polkit-1/localauthority/50-local.d/
    sudo tee /etc/polkit-1/localauthority/50-local.d/45-allow-colord.pkla <<'EOF'
    [Allow Colord for all users]
    Identity=unix-user:*
    Action=org.freedesktop.color-manager.create-device;org.freedesktop.color-manager.create-profile;org.freedesktop.color-manager.delete-device;org.freedesktop.color-
  manager.delete-profile;org.freedesktop.color-manager.modify-device;org.freedesktop.color-manager.modify-profile
    ResultAny=no
    ResultInactive=no
    ResultActive=yes
    EOF
    
    sudo tee /etc/polkit-1/localauthority/50-local.d/46-allow-networkmanager.pkla <<'EOF'
    [Allow Network Control for all users]
    Identity=unix-user:*
    Action=org.freedesktop.NetworkManager.network-control
    ResultAny=yes
    ResultInactive=yes
    ResultActive=yes
    EOF
    
    # [CHANGE] 7. Enable and Start Remote Desktop Services
    sudo systemctl daemon-reload
    sudo systemctl enable --now xrdp
    sudo systemctl enable --now xrdp-sesman

    ss -tlpn | grep -E "3389|xrdp"
    # Expected: LISTEN on 0.0.0.0:3389 (xrdp) and 127.0.0.1:3350 (sesman)

  ## 13. VDI Optimization

  Apply conservative, reversible optimizations to minimize storage and memory thrashing:

    # [CHANGE] 1. Reduce Swappiness (Virtual desktops perform poorly when memory is aggressively paged)
    sudo tee /etc/sysctl.d/99-vdi-performance.conf <<'EOF'
    vm.swappiness=10
    vm.vfs_cache_pressure=50
    EOF
    sudo sysctl --system
    
    # [CHANGE] 2. Enable Periodic TRIM for VirtIO Thin Disks
    sudo systemctl enable fstrim.timer
    
    # [CHANGE] 3. Disable Apport Crash Daemon (Eliminates user popups and CPU spikes)
    sudo systemctl mask apport.service
    
    # [CHANGE] 4. Limit Systemd Journal Retention to 100MB
    sudo mkdir -p /etc/systemd/journald.conf.d/
    sudo tee /etc/systemd/journald.conf.d/size-limit.conf <<'EOF'
    [Journal]
    SystemMaxUse=100M
    RuntimeMaxUse=50M

  ## 15. Clone-Safety Cleanup & Generalization

  Before converting the VM to a template, all machine-specific identifiers must be reset:

  • cloud-init: cloud-init clean --logs --seed resets instance cache so new clones run their own initialization.
  • machine-id: /etc/machine-id truncated to 0 bytes so systemd regenerates a unique ID on clone boot (prevents DHCP IP collisions).
  • SSH Host Keys: /etc/ssh/ssh_host_* deleted so each clone generates unique cryptographic fingerprints.
  • DHCP Leases & Network State: Purged so no MAC or IP bindings persist.
  • Test Users: vdi-test deleted with home directory removed.

  ## 25. Troubleshooting Guide

  ### 1. xrdp Session Shows Blank or Black Screen on Login

  • Likely Cause: Missing or malformed .xsession or conflict with GNOME/Wayland environment variables.
  • Diagnostic: cat /var/log/xrdp.log and cat /var/log/xrdp-sesman.log.
  • Fix: Ensure /etc/skel/.xsession contains exec /usr/bin/xfce4-session and copy to user profile:
    cp /etc/skel/.xsession ~/.xsession && chown $USER:$USER ~/.xsession


  ### 2. Polkit Pop-up "Authentication is required to create a color managed device"

  • Likely Cause: colord daemon queries PolicyKit upon remote display connection.
  • Fix: Deploy /etc/polkit-1/localauthority/50-local.d/45-allow-colord.pkla as shown in Section 9.1, then restart Polkit: sudo systemctl restart polkit.

  ### 3. Duplicate IP Address or DHCP Failures Across Clones

  • Likely Cause: /etc/machine-id was not truncated prior to template conversion. Netplan derives DHCP client identifiers from machine-id.
  • Fix: Inside the clone:
    sudo truncate -s 0 /etc/machine-id
    sudo systemd-machine-id-setup
    sudo netplan apply


  ### 4. QEMU Guest Agent Not Responding on Proxmox

  • Likely Cause: Daemon inactive or virtual hardware lacks agent: 1.
  • Diagnostic: On host: qm agent <VMID> ping. Inside guest: systemctl status qemu-guest-agent.
  • Fix: Ensure VM has agent: 1 (qm set <VMID> --agent enabled=1) and inside guest: sudo systemctl enable --now qemu-guest-agent.

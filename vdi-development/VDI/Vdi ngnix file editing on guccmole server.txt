Below is a corrected, production-ready SOP for deploying the Nginx Guacamole configuration on 10.31.7.213. It includes pre-checks, evidence collection, backup verification, controlled editing, guarded reload, functional validation, and rollback.

Production Nginx Change Procedure
1. Change scope

This change will:

Preserve the existing TLS policy.
Remove the obsolete ssl on; directive.
Preserve both Guacamole WebSocket paths.
Preserve /guacamole/ and root application proxying.
Remove document-export artifacts.
Validate the configuration before reload.
Use an Nginx reload rather than a restart.
Provide a verified rollback path.

Nginx requires the WebSocket Upgrade and Connection headers to be passed explicitly to the upstream service. Increased proxy_read_timeout values also help support long-lived WebSocket connections.

2. Pre-change checks

2.1 Start a root shell

To prevent environment variables from being lost between steps:

sudo -i


Enable pipeline failure detection:

set -o pipefail


Do not use set -e for this procedure because commands such as diff and grep can return a nonzero result during normal operation.

2.2 Define change variables

NGINX_LINK="/etc/nginx/sites-enabled/default"
TARGET_URL="https://10.31.7.213/"
BACKEND_URL="http://127.0.0.1:8080/guacamole/"
CHANGE_TIMESTAMP=$(date +%F-%H%M%S)

ACTIVE_PATH_FILE="/tmp/nginx-active-config-path.txt"
BACKUP_PATH_FILE="/tmp/nginx-backup-path.txt"
BASELINE_FILE="/tmp/nginx-baseline-${CHANGE_TIMESTAMP}.txt"
EVIDENCE_FILE="/tmp/nginx-config-before-${CHANGE_TIMESTAMP}.txt"

2.3 Resolve the active configuration file

echo "=== Active Nginx configuration check ==="

if [ ! -e "$NGINX_LINK" ]; then
    echo "ERROR: $NGINX_LINK does not exist."
    exit 1
fi

ls -l "$NGINX_LINK"

NGINX_CONFIG=$(readlink -f "$NGINX_LINK")

if [ -z "$NGINX_CONFIG" ] || [ ! -f "$NGINX_CONFIG" ]; then
    echo "ERROR: Unable to resolve the active Nginx configuration file."
    exit 1
fi

printf '%s\n' "$NGINX_CONFIG" > "$ACTIVE_PATH_FILE"
chmod 0600 "$ACTIVE_PATH_FILE"

echo "Active configuration: $NGINX_CONFIG"

2.8 Validate the backend
echo "=== Guacamole backend baseline ==="

BACKEND_RESULT=$(
    curl -sS \
        --connect-timeout 5 \
        --max-time 15 \
        -o /dev/null \
        -w '%{http_code} %{time_total}' \
        "$BACKEND_URL"
)
BACKEND_CURL_RC=$?

if [ "$BACKEND_CURL_RC" -ne 0 ]; then
    echo "ERROR: Unable to reach the Guacamole backend."
    exit 1
fi

BACKEND_HTTP=$(printf '%s\n' "$BACKEND_RESULT" | awk '{print $1}')
BACKEND_TIME=$(printf '%s\n' "$BACKEND_RESULT" | awk '{print $2}')

echo "Backend HTTP=$BACKEND_HTTP time=$BACKEND_TIME"

case "$BACKEND_HTTP" in
    200|301|302)
        echo "Backend response accepted."
        ;;
    *)
        echo "ERROR: Unexpected backend HTTP status: $BACKEND_HTTP"
        exit 1
        ;;
esac


If production currently uses another expected response code, document it in the change record before adding it to the accepted list.

3. Create and verify the backup
echo "=== Nginx configuration backup ==="

NGINX_CONFIG=$(cat "$ACTIVE_PATH_FILE")

if [ -z "$NGINX_CONFIG" ] || [ ! -f "$NGINX_CONFIG" ]; then
    echo "ERROR: Active Nginx configuration path is invalid."
    exit 1
fi

BACKUP_DIR="/var/backups/nginx"
BACKUP_FILE="$BACKUP_DIR/default.backup-${CHANGE_TIMESTAMP}"

install -d -m 0700 "$BACKUP_DIR"

if ! cp -a "$NGINX_CONFIG" "$BACKUP_FILE"; then
    echo "ERROR: Failed to create the Nginx configuration backup."
    exit 1
fi

printf '%s\n' "$BACKUP_FILE" > "$BACKUP_PATH_FILE"
chmod 0600 "$BACKUP_PATH_FILE"


Verify the backup:

if cmp -s "$NGINX_CONFIG" "$BACKUP_FILE"; then
    echo "Backup verified successfully: $BACKUP_FILE"
else
    echo "ERROR: Backup content does not match the active configuration."
    exit 1
fi


Record checksums and metadata:

sha256sum "$NGINX_CONFIG" "$BACKUP_FILE"
stat "$BACKUP_FILE"


The two SHA-256 values must be identical.

4. Updated production configuration

Edit the resolved configuration:

NGINX_CONFIG=$(cat "$ACTIVE_PATH_FILE")
vim "$NGINX_CONFIG"


Use this configuration:

server {
    listen 443 ssl;
    server_name localhost;

    add_header X-Frame-Options "SAMEORIGIN";

    ssl_certificate /etc/nginx/ssl/nginx.crt;
    ssl_certificate_key /etc/nginx/ssl/nginx.key;

    # Existing TLS policy retained.
    # TLS hardening must be handled under a separate approved change.
    ssl_session_cache builtin:1000 shared:SSL:10m;
    ssl_protocols TLSv1.1 TLSv1.2;
    ssl_ciphers HIGH:!aNULL:!eNULL:!EXPORT:!CAMELLIA:!DES:!MD5:!PSK:!RC4;
    ssl_prefer_server_ciphers on;

    access_log /var/log/nginx/localhost.access.log;
    error_log /var/log/nginx/error.log;

    error_page 500 502 503 504 /error.html;

    location = /error.html {
        root /usr/share/nginx/html;
        internal;
    }

    # Short Guacamole WebSocket endpoint
    location = /websocket-tunnel {
        proxy_pass http://127.0.0.1:8080/guacamole/websocket-tunnel;

        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_buffering off;
        proxy_connect_timeout 10s;
        proxy_read_timeout 86400s;
        proxy_send_timeout 86400s;
    }

    # Standard Guacamole WebSocket endpoint
    location = /guacamole/websocket-tunnel {
        proxy_pass http://127.0.0.1:8080/guacamole/websocket-tunnel;

        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_buffering off;
        proxy_connect_timeout 10s;
        proxy_read_timeout 86400s;
        proxy_send_timeout 86400s;
    }

    # Standard Guacamole application path
    location /guacamole/ {
        proxy_pass http://127.0.0.1:8080/guacamole/;

        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_buffering off;
        proxy_connect_timeout 10s;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }

    # Root path forwarded to Guacamole
    location / {
        proxy_pass http://127.0.0.1:8080/guacamole/;

        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_buffering off;
        proxy_connect_timeout 10s;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
}


For normal proxy requests, Nginx removes a request header when proxy_set_header assigns it an empty value. Therefore, proxy_set_header Connection ""; is valid for the non-WebSocket locations.

7.4 Application validation

Perform these final operational tests:

Open the Guacamole URL from an approved client.
Confirm that the login page loads.
Log in with a test account.
Start a remote desktop or SSH session.
Confirm keyboard and mouse interaction.
Keep the session open long enough to confirm stability.
Confirm no 502, 503, or 504 errors appear.

An HTTP response alone does not prove that an interactive WebSocket-based Guacamole session is operating correctly.

8. Rollback procedure

Rollback if:

Nginx is not active after reload.
The frontend becomes unavailable.
Unexpected HTTP status codes are returned.
Guacamole login fails because of the change.
Remote sessions fail to establish.
WebSocket or upstream errors appear.
Production users experience change-related disruption.
8.1 Restore the backup
echo "=== Nginx rollback ==="

NGINX_CONFIG=$(cat "$ACTIVE_PATH_FILE")
BACKUP_FILE=$(cat "$BACKUP_PATH_FILE")

if [ -z "$NGINX_CONFIG" ] || [ ! -f "$NGINX_CONFIG" ]; then
    echo "ERROR: Active configuration path is invalid."
    exit 1
fi

if [ -z "$BACKUP_FILE" ] || [ ! -f "$BACKUP_FILE" ]; then
    echo "ERROR: Backup file is unavailable."
    exit 1
fi

if ! cp -a "$BACKUP_FILE" "$NGINX_CONFIG"; then

    exit 1

sha256sum "$BACKUP_FILE" "$NGINX_CONFIG"

if ! systemctl reload nginx; then

Main improvements

This procedure uses the resolved configuration path consistently, validates real HTTP response codes, checks ports 443 and 8080 separately, safeguards the reload with a final syntax test, preserves production TLS compatibility, and provides a fully verified rollback route.

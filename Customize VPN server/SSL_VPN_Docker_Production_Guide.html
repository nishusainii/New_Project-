1. Executive Summary & Architecture

The Innspark SSL VPN is an enterprise-grade, zero-dependency TLS tunnel and gateway service built exclusively on the Python standard library (ssl, asyncio, socket, fcntl). It establishes high-throughput, low-latency cryptographic tunnels carrying IPv4/IPv6 traffic between remote clients and the internal network or Internet.

Key Architectural Highlights:
• Zero Third-Party Dependencies: 100% pure Python stdlib; immune to supply-chain package tampering.
• Dual-Tier Docker Stack: Dedicated TLS tunnel gateway on port 443 and isolated Web GUI Management Console on port 8080/8443.
• Hot-Reloading User Store: User additions, deletions, and ACL edits made in the Web Portal immediately sync to the active VPN daemon without restarting the container.
• Two Runtime Profiles: Mock TUN mode for safe, unprivileged testing and Real TUN mode with kernel IP forwarding & iptables NAT masquerading.

System Component Diagram

Kernel TUN (ssl0) Host Network Virtual L3 IP Device Bridges client packets into the host routing table with iptables MASQUERADE NAT.

2. Quick Start: Automated 1-Click Deployment

For fresh Ubuntu 22.04 or 24.04 installations, an automated deployment script (scripts/deploy_ubuntu.sh) configures the entire stack, hardening parameters, firewall rules, and container orchestration in a single command. 

# 1. Transfer or clone project directory to /opt/sslvpn
sudo mkdir -p /opt/sslvpn
sudo cp -r . /opt/sslvpn/
cd /opt/sslvpn

# 2. Execute the production deployment script as root
sudo bash scripts/deploy_ubuntu.sh

Upon completion, the script automatically reports the live status of the VPN daemon and outputs the Web Management Portal URL (e.g. http://<SERVER_PUBLIC_IP>:8080).

3. Step-by-Step Manual Deployment Guide

For administrators configuring the server step-by-step or integrating into existing configuration management systems (Ansible, Terraform, Puppet):

Step 1: Install Base Packages & Docker

sudo apt-get update -y && sudo apt-get upgrade -y
sudo apt-get install -y curl git openssl iptables iproute2 ufw python3 docker.io docker-compose-v2
sudo systemctl enable --now docker

Step 2: Apply Linux Kernel Network Hardening

Create /etc/sysctl.d/99-sslvpn.conf to enable IP forwarding and BBR congestion control:

sudo tee /etc/sysctl.d/99-sslvpn.conf << 'EOF'
# Enable Packet Forwarding
net.ipv4.ip_forward = 1
net.ipv6.conf.all.forwarding = 1

# BBR Congestion Control for Low Latency VPN
net.core.default_qdisc = fq
net.ipv4.tcp_congestion_control = bbr

# Anti-Spoofing & SYN Flood Defense
net.ipv4.tcp_syncookies = 1
net.ipv4.conf.all.rp_filter = 1
net.ipv4.conf.default.rp_filter = 1

# High-Throughput Network Buffers
net.core.rmem_max = 16777216
net.core.wmem_max = 16777216
net.ipv4.tcp_rmem = 4096 87380 16777216
net.ipv4.tcp_wmem = 4096 65536 16777216
EOF

sudo sysctl --system

Step 3: Generate Production TLS Certificates with SAN

cd /opt/sslvpn
# Automatically injects your Server's IP address or domain name into the Subject Alternative Name
bash scripts/generate_certs.sh YOUR_SERVER_PUBLIC_IP

# Lock down private key permissions
chmod 600 certs/*.key

Step 4: Enable Host NAT Masquerading

sudo bash scripts/setup_network.sh

Step 5: UFW Firewall Hardening

sudo ufw allow 22/tcp comment "SSH Remote Administration"
sudo ufw allow 443/tcp comment "SSL VPN Tunnel"
sudo ufw allow 8080/tcp comment "SSL VPN Web Portal"
sudo ufw --force enable

Step 6: Launch Container Stack

docker compose up -d
docker compose ps

Step 7: Auto-Start Web Portal via Systemd

sudo cp scripts/sslvpn-gui.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now sslvpn-gui

4. Production Security Hardening Matrix

Security Layer Production Setting Technical Rationale
Brute-Force Protection Token bucket rate-limiter (5 attempts, 900s lockout) Protects against automated credential stuffing. Excess failed logins receive HTTP 429 Too Many Requests.
Password Hashing PBKDF2-HMAC-SHA256 (200,000 rounds) Stored with cryptographic random salts. Resistant to GPU-accelerated rainbow table and offline dictionary attacks.
Cryptographic Keys chmod 600 certs/*.key Restricts read access to the root/container process only, preventing unauthorized extraction.
Admin IP Whitelisting sudo ufw allow from <IP> to any port 8080 Hides the Web Management Console from global port scanners and unauthorized networks.
Container Sandboxing Read-only mounts for static code (:ro) Ensures application templates and scripts cannot be modified or poisoned by compromised sub-processes.
High Availability restart: unless-stopped + Restart=always Automatic recovery upon host reboots or memory eviction events without requiring manual intervention.

5. Web Management Portal & User Administration

The Web GUI is accessible at http://<SERVER_IP>:8080 (or over HTTPS via --ssl on port 8443).

Default Administrative Credentials:

  • Username: admin
  • Initial Password: admin123 Change immediately after first login

User Management Operations:

  • Add User: Open the Users & Access tab → Click Add New User. Enter username, password, optional static VPN IP (e.g. 10.8.0.55), allowed subnet CIDRs (e.g. 0.0.0.0/0), and bandwidth limits (kbps).
  • Live Sync: Creating or modifying users saves to config/users.json and recalculates a SHA-256 hash. The VPN daemon detects the modification and loads the user immediately with zero client drops.
  • Disable / Enable: Click the status toggle button in the user row to instantly suspend or restore VPN access.

6. Client Connection Manual

Option A: Mock Mode (Testing & Validation without Root)

python3 vpn_client.py --server <SERVER_IP> --port 443 --username admin --mock-tun

Option B: Real Kernel TUN Mode (Full OS Routing - Requires Root)

sudo python3 vpn_client.py --server <SERVER_IP> --port 443 --username admin

Option C: Containerized Client (Docker)

docker run --rm -it --network host --entrypoint python3 innspark/sslvpn:1.0.0 \
    vpn_client.py --server <SERVER_IP> --port 443 --username admin --mock-tun

2. Verified Active Client Connections

Checked active connections to proxy ports:

ss -tn | grep :8860
ss -tn | grep :8859
ss -tn | grep :8878


Observed multiple client systems connected to Squid, confirming users were actively using the proxy.

3. Checked Squid Access Logs

Reviewed CONNECT requests and client activity:

grep CONNECT /var/log/squid/access.log


Verified traffic was flowing through Squid.

4. Captured WAN Traffic

Performed packet captures:

tcpdump -ni kv1 host 8.8.8.8
tcpdump -ni kv2 host 8.8.8.8


Observed DNS and Internet traffic on active WAN links.

5. Verified Squid Outbound Connections

Checked outbound Squid sessions:

ss -tnp | grep squid
lsof -iTCP -nP | grep squid


Confirmed Squid was creating Internet connections using multiple source IPs:

192.168.14.30
192.168.16.30
192.168.12.30
192.168.1.30
192.168.4.30
192.168.19.30

6. Reviewed Squid WAN Mapping Configuration

Verified tcp_outgoing_address configuration:

tcp_outgoing_address 192.168.14.30 proxy8860
tcp_outgoing_address 192.168.16.30 proxy8859
tcp_outgoing_address 192.168.12.30 proxy8878
tcp_outgoing_address 192.168.18.30 proxy8855
tcp_outgoing_address 192.168.8.30  proxy8868
tcp_outgoing_address 192.168.1.30  proxy8888
tcp_outgoing_address 192.168.4.30  proxy8898
tcp_outgoing_address 192.168.19.30 proxy8858
tcp_outgoing_address 192.168.5.30  proxy8848
tcp_outgoing_address 192.168.1.31 proxy8899


Confirmed each proxy port is mapped to a dedicated ISP/WAN interface.

7. Checked Interface Traffic Statistics

Monitored WAN interfaces:

ip -s link show kv1

...


Traffic observed on:

8. Investigated Inactive WAN Links

Tested gateway connectivity:

ping 192.168.18.1
ping 192.168.8.1
ping 192.168.5.1


Results:

192.168.18.1 unreachable
192.168.8.1 unreachable
192.168.5.1 unreachable


No ARP responses were received from these gateways.

9. Identified Root Cause

Confirmed that the ISPs associated with:

kv4  -> 192.168.18.x
kv5  -> 192.168.8.x
kv9  -> 192.168.5.x


had unpaid bills and services were suspended.

Therefore:

Gateway unreachable
No RX traffic
No Squid outbound traffic


is expected behavior.

Final Conclusion

✅ Squid configuration is correct.

✅ tcp_outgoing_address is functioning properly.

✅ Traffic is being routed separately through:

kv1 (8860)
kv2 (8859)
kv3 (8878)
kv6 (8888)
kv7 (8898)
kv8 (8858)


✅ Multi-WAN traffic separation is working as designed.

✅ Issue resolved.

❌ kv4, kv5, and kv9 are inactive due to ISP service suspension (unpaid bills), not because of a Squid or Linux configuration issue.

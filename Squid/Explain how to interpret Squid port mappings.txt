How to Interpret Squid Port Mappings

In your environment, each Squid listening port is intentionally mapped to a specific ISP/WAN interface using tcp_outgoing_address.

Configuration Example
tcp_outgoing_address 192.168.14.30 proxy8860
tcp_outgoing_address 192.168.16.30 proxy8859
tcp_outgoing_address 192.168.12.30 proxy8878
tcp_outgoing_address 192.168.18.30 proxy8855
tcp_outgoing_address 192.168.8.30  proxy8868
tcp_outgoing_address 192.168.1.30  proxy8888
tcp_outgoing_address 192.168.4.30  proxy8898
tcp_outgoing_address 192.168.19.30 proxy8858
tcp_outgoing_address 192.168.5.30  proxy8848
tcp_outgoing_address 192.168.1.31  proxy8899

How We Verified It
Step 1: Verify Mapping Exists
grep tcp_outgoing_address /etc/squid/squid.conf

Step 2: Verify Clients Use Proxy Ports
ss -tn | grep :8860
ss -tn | grep :8859
ss -tn | grep :8878

Step 3: Verify Outbound Source IP
lsof -iTCP -nP | grep squid | grep ESTABLISHED

Final Interpretation

When a user configures:

Proxy = 10.31.1.159:8860


their Internet traffic must exit through kv1 (192.168.14.30).

When a user configures:

Proxy = 10.31.1.159:8859


their Internet traffic must exit through kv2 (192.168.16.30).

This is exactly what your live Squid connections and interface counters confirmed.
